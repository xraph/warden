Warden works as a standalone Go library without any Forge dependency.

## Basic Setup

```go
package main

import (
    "context"
    "fmt"
    "log"

    "github.com/xraph/warden"
    "github.com/xraph/warden/assignment"
    "github.com/xraph/warden/permission"
    "github.com/xraph/warden/role"
    "github.com/xraph/warden/store/memory"
)

func main() {
    // Every check and every write is scoped to a tenant.
    ctx := warden.WithTenant(context.Background(), "docs-app", "acme")

    // 1. Create store
    st := memory.New()

    // 2. Create engine. RBAC, ABAC and ReBAC are all on by default.
    eng, err := warden.NewEngine(warden.WithStore(st))
    if err != nil {
        log.Fatal(err)
    }

    // 3. Set up roles and permissions. IDs and timestamps are
    // auto-assigned by the store on Create.
    if err := st.CreatePermission(ctx, &permission.Permission{
        TenantID: "acme", Name: "document:read", Resource: "document", Action: "read",
    }); err != nil {
        log.Fatal(err)
    }

    r := &role.Role{TenantID: "acme", Name: "Viewer", Slug: "viewer"}
    if err := st.CreateRole(ctx, r); err != nil {
        log.Fatal(err)
    }
    if err := st.AttachPermission(ctx, "acme", r.ID, permission.Ref{Name: "document:read"}); err != nil {
        log.Fatal(err)
    }

    if err := st.CreateAssignment(ctx, &assignment.Assignment{
        TenantID:    "acme",
        RoleID:      r.ID,
        SubjectKind: "user",
        SubjectID:   "user-1",
    }); err != nil {
        log.Fatal(err)
    }

    // 4. Check authorization
    result, err := eng.Check(ctx, &warden.CheckRequest{
        Subject:  warden.Subject{Kind: warden.SubjectUser, ID: "user-1"},
        Action:   warden.Action{Name: "read"},
        Resource: warden.Resource{Type: "document", ID: "doc-1"},
    })
    if err != nil {
        log.Fatal(err)
    }
    fmt.Printf("Allowed: %v (%s)\n", result.Allowed, result.Decision) // Allowed: true (allow)
}
```

These writes go straight to the store, so they don't fire the engine's hooks. That's fine here because there's no cache yet. See [With Caching](#with-caching) for what changes when there is one.

## Tenant Scoping (Standalone)

Without Forge, set tenant context using Warden's context helpers:

```go
ctx = warden.WithTenant(ctx, "myapp", "tenant-123")

// All subsequent operations are scoped to this tenant
result, _ := eng.Check(ctx, req)
```

## With PostgreSQL

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/pgdriver"
    _ "github.com/xraph/grove/drivers/pgdriver/pgmigrate" // Migrate needs the executor
    "github.com/xraph/warden/store/postgres"
)

drv := pgdriver.New()
if err := drv.Open(ctx, os.Getenv("DATABASE_URL")); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(drv)
if err != nil {
    log.Fatal(err)
}

pgStore := postgres.New(db)
defer pgStore.Close()
if err := pgStore.Migrate(ctx); err != nil {
    log.Fatal(err)
}

eng, err := warden.NewEngine(warden.WithStore(pgStore))
```

## With Caching

```go
import "github.com/xraph/warden/cache"

lru := cache.NewMemory(cache.WithTTL(5*time.Minute), cache.WithMaxSize(10000))

eng, _ := warden.NewEngine(
    warden.WithStore(st),
    warden.WithCache(lru),
)
```

With a cache configured, the engine drops affected entries when roles, permissions, assignments, relations or policies change, but only through its hooks. Those fire from the management API, the dashboard and the DSL applier. A write you make straight to the store, like the ones in the basic setup above, fires nothing, so a cached decision can outlive it until the TTL runs out. After writing to the store directly, call `eng.InvalidateTenant(ctx, tenantID)` or `eng.InvalidateSubject(ctx, tenantID, kind, id)` yourself.

## With Plugins

```go
import (
    glog "github.com/xraph/go-utils/log"
    "github.com/xraph/warden/plugin/auditlog"
)

eng, _ := warden.NewEngine(
    warden.WithStore(st),
    warden.WithPlugin(auditlog.New(glog.NewProductionLogger())), // one log line per audit event
)
```

There's no Chronicle audit plugin or Prometheus plugin package. Metrics go through `warden.WithMetrics`, or `warden.WithMetricsSink` with a go-utils metrics collector, and spans go to whatever OpenTelemetry tracer provider you install with `otel.SetTracerProvider` ([Monitoring](/docs/operations/monitoring) lists both). Anything else you want on an audit event you write as your own `plugin.Audit`. See [Plugin System](/docs/integration/plugin-system).
