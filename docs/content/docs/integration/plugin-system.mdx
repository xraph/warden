Warden's plugin system lets you hook into lifecycle events for audit logging, metrics, and custom behavior.

## Base Interface

Every plugin must implement the `Plugin` interface:

```go
import "github.com/xraph/warden/plugin"

type Plugin interface {
    Name() string
}
```

## Lifecycle Hooks

Plugins opt into hooks by implementing additional interfaces. Every hook method returns an `error`; a returned error is logged as a warning and never blocks the mutation that triggered it (see [Error handling](#error-handling) below). Where a request or result type is `*warden.CheckRequest` or `*warden.CheckResult`, the hook interface takes it as `any` instead, because `plugin` cannot import the root `warden` package without creating an import cycle.

### Check Hooks

```go
type BeforeCheck interface {
    OnBeforeCheck(ctx context.Context, req any) error // req is *warden.CheckRequest
}

type AfterCheck interface {
    OnAfterCheck(ctx context.Context, req, result any) error // *warden.CheckRequest, *warden.CheckResult
}
```

### Role Hooks

```go
type RoleCreated interface {
    OnRoleCreated(ctx context.Context, r *role.Role) error
}
type RoleUpdated interface {
    OnRoleUpdated(ctx context.Context, r *role.Role) error
}
type RoleDeleted interface {
    OnRoleDeleted(ctx context.Context, roleID id.RoleID) error
}
```

### Permission Hooks

```go
type PermissionCreated interface {
    OnPermissionCreated(ctx context.Context, p *permission.Permission) error

type PermissionDeleted interface {
    OnPermissionDeleted(ctx context.Context, permID id.PermissionID) error
}
type PermissionAttached interface {
    OnPermissionAttached(ctx context.Context, roleID id.RoleID, permID id.PermissionID) error
}
type PermissionDetached interface {
    OnPermissionDetached(ctx context.Context, roleID id.RoleID, permID id.PermissionID) error
}
```

### Assignment Hooks

```go
type RoleAssigned interface {
    OnRoleAssigned(ctx context.Context, a *assignment.Assignment) error
}
type RoleUnassigned interface {
    OnRoleUnassigned(ctx context.Context, a *assignment.Assignment) error

```

### Relation Hooks

```go
type RelationWritten interface {
    OnRelationWritten(ctx context.Context, t *relation.Tuple) error
}
type RelationDeleted interface {
    OnRelationDeleted(ctx context.Context, relID id.RelationID) error
}
```

### Policy Hooks

```go
type PolicyCreated interface {
    OnPolicyCreated(ctx context.Context, p *policy.Policy) error
}
type PolicyUpdated interface {
    OnPolicyUpdated(ctx context.Context, p *policy.Policy) error
}
type PolicyDeleted interface {
    OnPolicyDeleted(ctx context.Context, polID id.PolicyID) error
}
```

`PolicyObligationFired` fires once per `(policy, obligation)` pair after the engine has merged the RBAC/ReBAC/ABAC decision, so a plugin that reacts to obligations (`audit-log`, `require-mfa`, `notify-security`, ...) doesn't have to re-scan `CheckResult.Obligations` itself:

```go
type PolicyObligationFired interface {
    OnPolicyObligationFired(ctx context.Context, polID id.PolicyID, obligation string, req, result any) error
}
```

### Audit Hook

`Audit` fires for every mutation, in addition to whichever typed hook above also fires for it. Implement just this one interface if you want a single, complete audit stream instead of wiring up every typed hook individually:

```go
type Event struct {
    Actor     any // warden.Actor: Kind, ID, Via
    RequestID string
    TraceID   string
    At        time.Time
    Action    string // "role.created", "permission.attached", "declarative.applied", ...
    TenantID  string
    EntityID  string
    Entity    any // the entity after the change, nil on delete
    Before    any // the entity before an update, nil otherwise
}

type Audit interface {
    OnAudit(ctx context.Context, ev Event) error
}
```

### Shutdown Hook

```go
type Shutdown interface {
    OnShutdown(ctx context.Context) error
}
```

`Engine.Stop` calls `OnShutdown` on every plugin that implements it, after cancelling the maintenance loop and draining the check-log writer.

## Registering Plugins

```go
eng, _ := warden.NewEngine(
    warden.WithStore(store),
    warden.WithPlugin(&MyAuditPlugin{}),
    warden.WithPlugin(&MyMetricsPlugin{}),
)
```

## Type-Assertion Discovery

The plugin registry uses type assertions to discover which hooks each plugin implements. You only need to implement the hooks you care about:

```go
type MyPlugin struct{}

func (p *MyPlugin) Name() string { return "my-plugin" }

// Only implement OnAfterCheck: other hooks are ignored.
func (p *MyPlugin) OnAfterCheck(ctx context.Context, req, result any) error {
    res, _ := result.(*warden.CheckResult)
    log.Printf("check completed: allowed=%v", res.Allowed)
    return nil
}
```

If a plugin implements none of the known hook interfaces, `Registry.Register` logs a warning: that's almost always a wiring mistake (wrong signature, typo'd method name) rather than something you meant to do. `Registry.Validate(p)` returns the list of hook names a plugin implements, so you can assert on it in a test.

## Error handling

Every hook call is wrapped in a `recover()` and a nil-error check. A plugin that panics, or returns a non-nil error, is logged (`plugin hook panicked` or `plugin hook error`) and counted against the `warden_hook_errors_total{hook,plugin}` metric, but the mutation or check that triggered it always completes: one misbehaving plugin can neither crash the engine nor block the rest of the dispatch loop for that event.

## Built-in Plugins

### Audit log plugin (`plugin/auditlog`)

`plugin/auditlog` is Warden's in-tree `Audit` sink. It writes one structured `Info` line per audit event through a `go-utils/log.Logger` (which `forge.Logger` satisfies directly):

```go
import "github.com/xraph/warden/plugin/auditlog"

eng, _ := warden.NewEngine(
    warden.WithStore(store),
    warden.WithPlugin(auditlog.New(logger)),
)
```

The Forge extension registers this plugin automatically. It's what `auth.audit_log: true` (the default) turns on. See [Forge Extension](/docs/integration/forge-extension) and [Monitoring](/docs/operations/monitoring) for the fields on each log line.

There's no separate `audit_hook`/Chronicle package and no `observability`/Prometheus plugin package. Metrics are wired through `warden.WithMetrics` (or, under the Forge extension, automatically from `Extension.Metrics()`) instead of a plugin. See [Monitoring](/docs/operations/monitoring) for the full metric list.
